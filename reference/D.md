## D. 公式化排版

### 二值检查单

判定单位是「段 × 条目」：每个（段，条目）组合都要判一次。同一段可以同时命中多条，同一条目也可以命中多段，按条目分别列，不要每段只取一条。只有全文都不命中才写「不命中」；命中附段号、原句（逐字）和一句依据；判不了记「待定」，不计入命中。

- **D1 粗体当装饰**：粗体是否只起强调、不帮跳读（句内随手加粗）？
- **D2 装饰性标题**：标题是否带表情符号、装饰箭头或分隔线而妨碍阅读？
- **D3 引号与中文标点**：中文正文是否用了英文引号或混用直引号？

### D1. 粗体当装饰

减少没有帮助的强调，保留跳读所需的重点。不设固定粗体数量，不因去掉排版而删掉括号解释、比较或列表项。

**改写前：** 支持 **CSV（逗号分隔值）** 和 **JSON** 导出。

**改写后：** 支持 CSV（逗号分隔值）和 JSON 导出。

**保留：** 警告中的关键操作与长文里帮助定位的重点。

### D2. 装饰性标题

表情符号、箭头和分隔线妨碍阅读时可调整；状态标记（“✅ 已通过”“⚠️ 注意”）承载含义时保留。结构本身不是问题；标题结构和锚点按文件保护规则处理，标题文字按 [H.md](H.md) 处理。英文标题大小写遵守目标格式。

**改写前（粘贴文本）：** 🚀 发布安排：产品计划在第三季度发布。

**改写后：** 发布安排：产品计划在第三季度发布。

**保留：** 发布计划不改成已发布，方向箭头承载流程含义时也保留。

### D3. 引号与中文标点

根据目标格式统一标点，不把中文正文改成英文标点。代码、原文引语和结构化数据遵守各自的保护要求。

**改写前：** 他说"项目进展顺利"，但其他人不同意。

**改写后：** 他说“项目进展顺利”，但其他人不同意。

**保留：** JSON 字符串中的直引号，以及用户指定的「」样式。
