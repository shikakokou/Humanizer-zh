## 可选修复：过度截短、省略与口语化

**单独的可选修复，不属于正文检查点。** 只用于技术和专业领域文本（算法与数据说明、API 与运维文档、工程报告、学术方法、专业分析）。开始检查前问一次要不要处理；用户同意就按这里改，拒绝或没要求就跳过，后面不再逐条问。用户一开始就明确要求处理时，直接改。

### O1. 先判断

1. 读者需要先想象一个画面或动作才能理解 → 换成直接描述。
2. 这个词是项目里稳定、精确的术语（管线、节点、断点、色板、描边）→ 保留。
3. 换完句子变模糊或信息变少 → 不换。
4. 省略主语、对象、条件或步骤，导致句子读不懂 → 按原文补回；原文没有的不编。

### O2. 电文体压缩

同一句或相邻分句里连续出现两个以上单字动词（不必紧挨着，如扫、数、断、记、取），或把同一篇文章里用过的术语截短（“连续子序列”写成“连续段”），就把成串的动作恢复成完整动词，术语用文章原词。

**改写前：** 从下标 0 往后扫，桶里有元素就接着数，遇到空桶就断开，记下最长的一段。

**改写后：** 从下标 0 开始遍历桶数组，相邻几个桶里都有元素，就说明对应的值连续；遇到空桶就断开，记录最长的一段。

**术语：** 同一篇里已经把“连续子序列”写全，草稿里的“连续段”改回“连续子序列”。文章没有给出全称时，不替它造一个。

### O3. 动作化与画面化

能直接说“先复制画布”“覆盖”“贴着”的，就直接说；不要用“兜住”“夹住”“闸住”“拍上去”这类要先想象动作的说法。具体动词按上下文换成常见表达或项目术语，不机械替换。

### O4. 口语与内部简称

把口语、内部简称换成明确的说法，例如“默认值”“实际颜色”“规则”“固定宽度判断”。不要为了省字把术语压成只有 AI 才知道是什么的简称。

禁止用下面这些词代替常见表达或计算机术语：

- 单字：兜、夹、闸、拍、判、调、碰、撞
- 名词/动词：对账、认人
- 状态：在飞、判死、判活、死没死、判对、判错、抢不到

单字不是见字就改：“判断”“调用”“碰撞检测”里的字是正常用词，保留；只有拿它作拟人化、口语化表达代替常见表达或计算机术语时才改。其余禁词按上下文换成直接说法，例如“在飞”改成“进行中”，“判死/判活”改成“判定失败/成功”，“死没死”改成“是否失败/是否还在运行”，“判对/判错”改成“判定正确/错误”，“抢不到”改成“未获取到”，“对账”改成“核对”，“认人”改成“识别身份/人物”。

**改写前：** 先把图层兜住，夹到画布边上，判一下颜色，再拍个默认值。

**改写后：** 先复制画布，把图层贴到边缘，按规则检查实际颜色，再写入默认值。

### O5. 先否定再转折

“不是……而是……”“虽然不……但……”如果只是绕路，直接说结论；对比本身是信息时保留。

**改写前：** 这里不是重绘，而是把新画面盖上去。

**改写后：** 这里把新画面覆盖到原画面上。

### O6. 保留边界

命令名（`cd`、`grep`）、代码标识、API 名和数学符号按原样保留。单字动词不按字数判断：按 O1 的几条看，读者不用猜对象、句意完整就保留；需要补对象或动作才清楚，才恢复成完整动词。
